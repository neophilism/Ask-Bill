# AB-023 — tenant/version lexical indexes and atomic generation activation

Implementation: immutable source-bound in-memory lexical search generation builder for local testing; SQL generation/entries/active-pointer tables with composite version/publisher foreign keys, forced row-level policies, exact source text/digest guards, immutable completed generation triggers, PostgreSQL full-text GIN index, and advisory-lock serialized generation activation with compare-and-swap expected previous pointer. Search queries use bound parameters and current active generation only.

Verification: Node source tests including unicode, version/tenant rejection, index tampering and stale activation; ephemeral PostgreSQL 17 migration runs twice, inserts two tenant fixtures, tests actual RLS, source hash, incomplete generation, completed generation mutability, stale writer rejection, atomic pointer revision, and transaction rollback. CI runs from the active `tests/postgres/integration.sh` gate.

Limits: search matching is a lexical aid, not proof of legal source accuracy or authoritative publication. Normalized match offsets must never be reused as exact citation positions; verify against original source by AB-018. UI, worker index scheduling, staging load test and source-release integration are not yet operationally accepted. Full AB-023 gate still requires real indexing activation/load tests against selected authoritative source packs.

Rollback: preserve previous complete generation/pointer and disable writes; do not destructively delete index history.
