# AB-021 — version lifecycle, enactment evidence, as-of freshness and explicit switches

Scoped implementation: immutable snapshots of selected source version, append-only independently source-supported status events, evidence SHA-256 plus official source URL and action dates, separate enacted and effective dates, stale-age warnings, incomplete/unknown source labels, and explicit change-of-version epoch invalidation of previous answers, citations, audio, tours and cached state.

Important: this is a **status model and fixture-tested policy**, not a live Congress.gov event history or full React/Next.js bill picker. The adapter never infers enactment from "latest action" text or automatically treats a draft as current law. Source changes must produce a new version ID, while old transcript/audio is invalidated on switch. Genuine official-source status reconciliation, publisher approval, staging and full browser accessibility are pending acceptance.

Verify via node --test tests/versions.test.mjs, static workspace quality, Chromium, PostgreSQL and PDF jobs on exact PR head. Rollback: retain prior version snapshots, disable new status updates/automatic refresh, display retrieval age and do not promote status.
