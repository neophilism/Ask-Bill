# AB-007 Tenant-scoped persistence schema — partial implementation evidence

Unit: AB-007; dependencies AB-003 and AB-005. Branch `ab-007-tenant-schema` built atop AB-005 PR #5 (which depends on PR #3 and earlier work).

Implementation: `migrations/001_initial.sql` declares 10 Ask Bill-owned PostgreSQL tables covering publishers, memberships, bills, immutable versions, provisions, short-lived anonymous sessions, deduplicated jobs, outbox, usage reservations and audit metadata. Includes composite publisher-safe foreign keys, release-completeness constraint, retention indexes, publisher-scoped row-level policies with FORCE RLS, and non-destructive DDL. `@ask-bill/db` provides parameterized query contracts and transaction-local tenant binding; no database credentials or actual DB client is included.

Local verification: Node 22.16.0, TypeScript 5.8.3; `tsc -p packages/db/tsconfig.json && node --test tests/db.test.mjs`. Three tests passed for schema/RLS and FK structural invariants, query parameterization and negative injection inputs. Exact Git blob hashes of SQL/source/tests matched locally tested files.

**Not yet accepted:** No PostgreSQL instance was available; no migration was applied; real two-tenant isolation tests, role permissions, schema idempotence against a live database, populated DB upgrade/rollback, fresh pnpm install, pinned Node 24 CircleCI, and API integration remain unverified. The unit remains partial/draft and must not merge ahead of AB-005's accepted head.

Security review: transaction-local setting is only safe when bound by trusted, authenticated server-side code. RLS does not prevent misuse by superusers or a role with BYPASSRLS. No credentials are accepted from the browser, and public version queries require an explicit published/complete version. This is a foundation schema, not an operable multi-tenant service.

Rollback: revert migration and isolated `@ask-bill/db` package in git; do not run destructive down migrations on populated data. Restore application version against the compatible schema.
