# AB-043 Privacy-minimized feedback, suppression and corrections — partial

Feedback requires an explicit user action, a preview of automatically redacted email/phone/identifiers/URLs/secrets, and a **second confirmation after the preview**. Ordinary questions and server-side conversation histories are not automatically captured. The API form is disabled for under-13 or unknown age bands until appropriate compliance and verified consent are configured. The retained feedback descriptor contains only the redacted voluntary comment, answer/source IDs, reason and a 90-day expiration target. Automated patterns are a **best effort**, not a guarantee that all personal information has been removed; users still review the text before submission.

A publisher incident ledger model retains immutable hashed audit metadata, immediately suppresses identified answer templates, and appends source-hash-bound visible correction notices without restoring the wrong answer. Owner MFA/authorization flags shown here must come only from trusted authenticated server code; a browser cannot grant this authority.

Outstanding full acceptance: real identity/MFA provider, durable tenant RLS incident/audit store, actual user-facing redaction preview, threat-tested PII classification, deletion/retention jobs, correction and suppression delivery to all caches/replicas, incident alerts. A process-local ledger is not evidence of persistent production controls. No third-party company integrations or Bill character dependency.
