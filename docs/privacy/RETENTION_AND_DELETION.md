# Data minimization, retention and deletion — Ask Bill AB-011

The machine-readable inventory is `docs/privacy/DATA_FLOWS.json`. It maps sensitive data flows to owning modules and approved work IDs, current implementation state, retention targets and verification cases. **Pending retention enforcement is not the same as an implemented deletion system.**

- **Reading and guided curated tours:** no login or public analytics dependency. Public packs are versioned and retained with provenance; no per-visitor behavioral profile. Avoid storing raw IP addresses in application data. Transport/security metadata requires a separate seven-day-or-less configured policy when deployed.
- **Anonymous questions and answer replay:** expected short-lived 30-minute server replay, default browser-session context, optional explicit feedback only. Raw questions never go to standard logs or analytics. These services are not enabled yet.
- **Voice:** microphone capture only after a clear user gesture and age/consent gate. Delete raw uploaded audio on successful transcription, with at most one-hour cleanup bound; do not store as a training example. STT/TTS vendors require independently validated retention configuration and terms before activation.
- **Children:** curated child route must not send free text or microphone samples to third parties. Under-13 live entry remains gated by parent-initiated verifiable consent and contractually acceptable provider handling. A simple checkbox is not verified consent. The standalone predicate in `packages/privacy/` does not establish parental identity or validate a third-party verification receipt.
- **Publisher private material:** quarantine seven days by default; private source retained only with publisher-directed purpose and access. Persist required publicly archived provenance without retaining unauthorized unpublished drafts. Expiration of a signed upload ticket is not deletion of an underlying object.
- **Feedback:** opt-in, redaction/preview first, target 90 days. **Audit metadata:** one year target; avoid storing raw prompts, transcripts, keys or private documents. **Security diagnostics:** allowlisted structured event, maximum seven-day target once service exists, disabled until an actual deletion configuration is verified.
- **Queue and outbox:** must preserve correct processing/recovery and deduplication. Current retention values are **unset/pending**, not indefinite authorization to retain payloads. Introduce a safe archival/deletion policy with tombstones, replay idempotency and backup treatment before production.

Deletion requests require authenticated or capability-proven subject identification, tenant-scoped access, immediate removal/disable of active records, deletion of owned object derivatives, provider-side deletion verification, backup expiry and tombstones replayed after restoration. Refuse cross-tenant deletion requests. Re-test the deletion trail following a staging backup/restore before enabling sensitive providers. Never claim that application deletion erases undisclosed copies held by an external provider.

To run policy checks after the workspace is installed: `node --test tests/privacy.test.mjs`, then full `pnpm verify`. This file and the inventory are an engineering design checkpoint, not a legal compliance certification.
